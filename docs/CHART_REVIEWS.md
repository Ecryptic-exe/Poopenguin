# 玩家匿名譜面評價

入口：`/chart` 或 `/score` → 搜尋／確認歌曲 → 選擇難度 → 功能選單 **評價／社群評價**。公開頁合併 Poopenguin 原表資料及玩家匿名統計；下方「撰寫／管理評價」選單的「新增／管理我的評價」另外開本人可見的私人訊息。同一選單亦提供有資料的玩家統計群組。

## 寫入與修改

1. 開啟私人評價管理頁時，自動讀取目前來源的本人資料，帶入可用的 Rating，並沿用已保存的主力等級、遊玩經驗及技能。NET／Kamaitachi 讀既有帳號流程；Chunirec／匯出檔讀已同步快照。資料讀不到時沿用已保存背景，缺少的項目標為「未提供」，不擋住評價。
2. 直接按「填寫譜面評價」或「修改譜面評價」，不必先確認背景。需要補充時才按次要按鈕「補充／更新玩家背景」；不會用遊玩次數或分數猜測主力等級、年資及技能。
3. 填喜好 1–5、相對定數的體感難度、這張譜面的遊玩次數、主要目標與文字評論。提交時將評價與本次讀取／補充的玩家資料快照一起存入資料庫。
4. 同一玩家對同一個實際 `chart_id` 只有一份目前評價；重新進入即可修改，舊值會預填。不同視窗同時編輯時，較舊版本會被拒絕，請重新開啟後再改。
5. 本人可「刪除此張評價」並再次確認；刪除同時移除該份修改紀錄。主資料的「刪除全部本機資料」也會移除本人的全部評價、背景及修改紀錄。

評價表單有五個欄位；背景表單改為選用。完整選項與逐層版面見 [Embed 介面清單](EMBED_UX_PROPOSAL.md)。

## 公開與私人資料

| 資料 | 公開歌曲卡 | 本人的私人管理頁／表單 |
|---|---|---|
| 喜好、體感難度 | 從一筆起顯示整體／群體統計 | 自己填寫的值 |
| Rating、主力等級、經驗 | 有資料時按其中一個維度分組 | 自動讀取及已保存的背景，可選擇補充 |
| 擅長／不擅長、遊玩次數、目標 | 目前不作公開分組 | 本人填寫的值 |
| 文字評論 | 不公開 | 本人的評論 |
| Discord 帳號、修改時間、歷史版本 | 不公開 | 帳號用於內部辨識編輯權；不提供公開清單 |

依目前要求，暫時取消五筆最低門檻與小群體隱藏：**一筆就能顯示統計**，分組也可顯示一人的資料。零筆顯示「尚無評價」。缺少的背景不建立「未提供」假群組；選單只列實際有資料的 Rating／主力等級／經驗分組，不提供交叉篩選。仍不公開帳號、個別評論或修改時間。

Rating 優先取目前來源可讀到的實際玩家 Rating；不以單曲 Rating 或 B50 平均推估取代。其餘背景沿用先前保存的自填資料。每次評價保留當時快照；之後玩家資料改變，不會改寫其他譜面的舊背景。公開頁重新選「評價／社群評價」即可讀取最新統計。

這裡的匿名指公開介面不顯示個人身分；本機資料庫仍有私有帳號關聯，供本人修改、刪除與防止重複評價。能直接讀取本機資料庫的管理者仍具有資料存取能力。

## 本機維護

新增三張表：`chart_reviewer_profiles`、`chart_player_reviews`、`chart_player_review_history`。不修改既有 Song／Chart ID、玩家資料或社群註記，也不自動填入假評價。

既有未記錄 Alembic 版本的資料庫，使用獨立的加表工具：

```powershell
.venv\Scripts\python.exe -m penguin review-schema
```

預設只檢查，不寫入。實際套用前，先停本專案機器人並建立一致性備份，再執行：

```powershell
.venv\Scripts\python.exe -m penguin review-schema --apply
```

工具驗證父譜面表、欄位／鍵／限制／索引、完整性與外鍵；只新增這三張表，不重跑舊遷移、不建立 Alembic 版本標記，重跑不重複建立。缺一部分表或結構不一致時會拒絕套用。已建立過但有內容的評價表，不允許透過 migration downgrade 刪掉。

本次排演與正式套用紀錄分別在 `reports/review-migration-rehearsal-20261016.json`、`reports/review-migration-live-20261016.json`；備份放在忽略追蹤的 `data/backups/reviews-*/before.sqlite3`。如需停用新功能，保留資料表並回復程式版本即可；不要為了退回介面就還原整份舊資料庫，避免覆蓋後續玩家更新。

沒有新增必要 `.env` 參數或 Windows 權限。
