# 既有玩家資料的遷移邊界

本次建立全新的本機資料庫。沒有修改、複製或遷移舊部署的玩家資料；`penguin init` 遇到任何已存在目標都會拒絕覆寫。

未來正式遷移必須由管理者另行決定並執行：

1. 停止寫入，使用 SQLite backup API 或停止程序後連同 WAL／SHM 一起保存一致備份。保存原設定及憑證金鑰，限制存取權限。
2. 在備份副本驗證 A 的現有 Song／Chart／PersonalBest schema 與版本。v2 額外需要 `v2_player_sources`，不能盲目重播歷史 Alembic migrations。
3. 新玩家預設 private。既有玩家的明確隱私偏好需審核處理；本次沒有對既有資料執行批次改寫。
4. 檢查使用者數、來源成績筆數、外鍵完整性、Cookie／Token 隔離，以及代表性帳號在私人環境中的查詢／登出／刪除。
5. 任一驗證失敗時恢復完整原備份與原版本。保留演練結果再安排正式遷移。

目前沒有提供或執行正式環境自動遷移。新來源快照／PB 寫入使用 A 的單一 serialized writer；解除綁定與同使用者同步共用鎖，避免刪除後重新寫回。資料庫刪除不會回溯清除既有管理者備份；需另有備份保存政策。
